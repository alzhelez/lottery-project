## 40.4.0_15102026

По первой полной загрузке с живого API: 30 игр, 920 тысяч тиражей, выплаты найдены во всех.

### Исправлено
- **Категории выплат сопоставляются с исходами билета по настоящим подписям API.**
  Раньше часть категорий не распознавалась или распознавалась неверно:
  * «4 X 3 и 3 X 4» (4 из 20, Охота) — одна категория на два исхода; раньше из подписи
    бралось «3 и 3» → «3+3», что неверно;
  * «5» в «5 из 36 плюс», «8» в Рапидо — совпадения без бонусного числа («5+0», «8+0»);
  * «2 или 10» (Crazy Combo, Остатки сладки) — одна категория на два исхода;
  * туры бинго, ставки на чётность и порядок цифр (Топ-3) — не исходы по числу совпадений,
    калькулятор их не использует.
- **Оценка методов в рублях считает по цене билета в каждом тираже**, а не по сегодняшней:
  цена «4 из 20» за историю менялась от 100 до 350 ₽, и возврат занижался (32% вместо
  реальных ~53%).
- **Формат игр по реестру:** «Охота» — два поля по 4 из 20 (было разобрано как 8 цифр);
  «Кено 2.0» — 9 цифр и 20 чисел из 80 (раньше сохранялись только 20 + 1 из 29 чисел —
  архив перекачается один раз автоматически); «Рапидо Про / Ультра / Драйв», «Лови момент» —
  8 + 1; «Crazy Combo», «Остатки сладки», vin, zabavaloto — 12 из 24; новая «7 из 49».
- Бинго (ФЗП, Рокетбинго) больше не помечаются «неполными тиражами»: число шаров в них
  меняется от тиража к тиражу.
- Выплаты не берутся из тиража, который ещё не закрыт (статус PLAYING): там пустые таблицы.

### Изменено
- **Одинаковые игры:** API отдаёт одни и те же тиражи под разными именами (5 из 36 лайт и
  лайт 2, Crazy Combo и Остатки сладки, Дважды два и Охота: вызов, vin и zabavaloto).
  Автозапуск анализирует только первую из пары, `diagnose` их перечисляет.
- **Файлы выплат вдвое меньше и не переписываются целиком** при каждой загрузке: новые
  тиражи дописываются в конец, строки компактные (у Рапидо 2.0 файл был 128 МБ). Старый
  формат читается и уплотняется при следующем перечитывании архива. Расчёты по выплатам
  в 3 раза быстрее и требуют в разы меньше памяти.
- Названия игр, которых нет в реестре, берутся из ответа API.
- Тесты на ответах настоящего API (по тиражу каждой из 30 игр).

## 40.3.2_13102026

Исправления по первой загрузке 40.3 с живого API Столото.

### Исправлено
- **Загрузка зависала на часы на играх с частыми тиражами** («Дважды два», «Охота: вызов» —
  тираж каждые 15 минут). Архив читается окнами по году, а в таком окне 35 тысяч тиражей:
  API отдаёт не дальше ~500-й страницы, а дальше бесконечно повторяет одну и ту же с
  признаком «есть ещё». Теперь повтор страницы распознаётся, окно уменьшается под частоту
  тиражей игры (для «Дважды два» — около трёх месяцев), и архив загружается целиком.
- **Выплаты не находились.** В ответе API о тираже три похожих списка; разбор брал самый
  длинный — `winners`, где одни нули и категории только номерами. Теперь выбирается список с
  подписями категорий и ненулевыми данными — `winCategories` (подписи вида «2 + 2»,
  «4 из 5», суммы в рублях); цена билета — `ticketPrice`. Проверено на ответах API с вашего
  компьютера.
- **«Дважды два» и «Охота: вызов» — два поля по 2 числа из 26**, а не одно поле из 4 чисел
  (видно по категориям «2 + 2», «1 + 2»…). Добавлена «4 из 20 мини» — два поля по 4.
  Игры не из реестра, где числа идут одним списком с повторами, делятся на равные поля без
  повторов автоматически.

### Изменено
- Первая загрузка после обновления **один раз перечитывает архив каждой уже скачанной игры**,
  чтобы собрать выплаты по всем старым тиражам: она дольше обычной (минуты на игру, для игр
  с тиражами каждые 15 минут — до получаса). Дальше — обычная докачка.
- `diagnose` отмечает игры, у которых API отдаёт одни и те же тиражи под разными именами
  («Дважды два» и «Охота: вызов» сейчас именно такие).
- Скачанные тиражи (`data/draws`) больше не хранятся в репозитории и образе Docker — это
  ваши данные, а не часть программы; иначе `update.bat` не мог бы обновить папку после
  загрузки. Тиражи «4 из 20» и «6 из 45 плюс» по-прежнему разворачиваются из
  `data/tirazh*.txt`.
- CI: упавшие тесты видны прямо на странице сборки (аннотации), без открытия журнала.

### Исправлено (по CI на Windows)
- Брошенные временные файлы с атрибутом «только для чтения» не удалялись.
- Тест подмены файла ломал запись результатов Allure.

  * Калькулятор шансов сам подставляет типичные выплаты (медиана за 50 тиражей) и цену;

- **Docker:** порт 3000 открыт только для этого компьютера (`127.0.0.1:3000`) — в приложении
  нет входа по паролю.

  тиражи, и если ему больше 14 дней.
- **Скорость на больших архивах:**

  * файл тиражей не переписывается, если новых тиражей нет;
  * режим Бога: голосование экспертов векторизовано (`np.bincount`), промежуточный пересчёт
    стратегий во время поиска — не чаще раза в 10 минут.

## 40.2.1_09102026

Исправления по первой загрузке с живого API Столото на Windows.

### Исправлено
- **PermissionError при сохранении тиражей** (WinError 5 / 32, Errno 13 — 14 игр из 31).
  Файл тиражей переписывался целиком каждые 5 страниц (для 17 тыс. тиражей — около 70 раз
  за загрузку), а Windows (Защитник, индексатор, OneDrive) держит только что записанный файл
  на время проверки — подмена падала. Теперь: файл пишется не чаще раза в 30 секунд; подмена
  повторяется с нарастающей паузой (до ~10 с), а если файл так и не освободился — данные
  пишутся поверх напрямую; у временного файла уникальное имя, брошенные `.tmp` удаляются.
  Так же пишутся все остальные файлы (журнал, результаты, состояние режима Бога).
- **Цифровые игры теряли нули.** Нули отбрасывались для всех игр, кроме отмеченных в реестре,
  а в API игра называется `top-3`, а не `top3`. Теперь 0 — законное значение для любой игры.
  Уже скачанные тиражи с потерянными числами при следующем `fetch` один раз перекачиваются
  автоматически (в выводе — «неполных тиражей: N», если что-то осталось).
- Строка «Игр к загрузке» выводилась дважды.

### Добавлено
- `lp.bat diagnose` — по каждой игре: число тиражей, пропуски, неполные тиражи, даты,
  актуальность, распределение длины строк, диапазоны чисел, определённый формат, первые и
  последние строки файла. Отчёт — `data\diagnose.txt`; с `--api` ещё и по два сырых ответа API
  на игру (`data\api_samples.json`).
- Названия игр берутся из ответа API (`data/api_games.json`), если игры нет в реестре.
  Список «игр без загруженных тиражей» показывает только активные по API игры.
- Игры не из реестра, у которых API отдаёт основное поле и бонус одним списком (например,
  «8 из 20» + «1 из 4»), разделяются на два поля автоматически по данным.
- В реестр добавлены названия из API: `top-3`, `rapidoultra`, `rapidodrive`, `rapidopro`.

## 40.2.0_08102026

### Добавлено
- **Автозапуск.** Команда `auto`: загрузка тиражей → сверка журнала → анализ всех активных
  игр с прогнозом на следующий тираж → проверка на случайность. `schedule.bat` создаёт задачу
  в Планировщике Windows (без окна консоли, журнал — `data/logs/auto.log`), `unschedule.bat`
  удаляет. Защита от одновременных запусков. На главной — статус последнего цикла и запуск
  вручную.
- **Калькулятор шансов.** Точные вероятности каждого исхода билета (гипергеометрическое
  распределение по полям), шанс главного приза, ожидаемый выигрыш и возврат с рубля по
  введённым цене и призам (`data/prizes/<игра>.json`). Страница «Шансы игр» сравнивает игры.
- **Генератор непопулярных комбинаций.** Отбрасывает «даты», месяцы, ряды подряд, прогрессии,
  кратные, одинаковые окончания и числа из прошлого тиража; билеты в наборе мало
  пересекаются. Проверка своей комбинации. Скачивание билетов в CSV.
- **Экспорт** тиражей, журнала, сравнения методов, тестов случайности и ленты режима Бога:
  всё в Excel (листы с фильтрами) или таблица в CSV (UTF-8 с BOM, «;», десятичная запятая).
- **Режим Бога продолжается после остановки.** Состояние пула экспертов сохраняется
  (`godmode_state.npz`), кнопка «Продолжить» / `--resume`. Поиск идёт до конца бюджета или до
  застоя (40 пачек без улучшения на первой половине — «перебор исчерпан»); пул ограничен
  800 экспертами, вытесняются слабейшие по первой половине, так что проверка по второй
  половине остаётся честной. Добавлен локальный поиск вокруг лучших смесей признаков.
  Запуск из консоли или Планировщика виден в приложении (lock-файл с PID и файл прогресса).
- **CI в GitHub Actions** (pytest на Linux и Windows, сквозные тесты, Allure-отчёт, публикация
  на GitHub Pages по переменной `ALLURE_PAGES`) и **Allure 3** локально (`npm run allure:report`).
- **Docker:** `Dockerfile` и `docker-compose.yml` (приложение + автозапуск раз в час).
- `setup.bat` предлагает установить Python и Node.js через `winget`, если их нет.

### Изменено
- Зависимости Python разделены: `requirements.txt` (работа) и `requirements-dev.txt` (тесты).
- Режим Бога больше не останавливается на 300 смесях признаков: используется бюджет.

## 40.0.0_07102026

Полная переработка. Подробности и обоснование — `docs/AUDIT.md`.

### Математика
- Новый движок прогноза: каждая модель строго причинна (прогноз на тираж t — только по
  тиражам до t), что проверяется тестом для всех ~80 моделей.
- Честная проверка методов: отбор на первых 2/3 истории, контроль на последней 1/3,
  сравнение с точным гипергеометрическим ожиданием, поправка Холма.
- Корректные тесты случайности: χ² с поправкой на выбор без возвращения и раздельно по
  полям, повторы через 1–2 тиража, устойчивость горячих чисел (перестановочный тест),
  автокорреляция сумм, равномерность пар (Монте-Карло); поправки Холма и Бенджамини–Хохберга.
- «Режим Бога» переписан как потиражная онлайн-адаптация: эксперты, мета-стратегии
  «лидер за W тиражей» и Hedge, выбор стратегии по первой половине и проверка по второй,
  стадии с сохранением промежуточного результата, бюджет до 8 часов.
- Детерминированный разрыв ничьих — прогнозы воспроизводимы и не смещены к малым числам.
- Используются все тиражи (раньше молча обрезалось до 5000 / 2000).

### Загрузка тиражей
- Исправлено: потеря нулей (цифровые игры), сканирование архива с 2009 года на каждый

- Быстрый отказ при отсутствии сети вместо ~1 минуты ретраев на каждую игру.
- Загружаются активные по API игры и уже скачанные; legacy-файлы сливаются автоматически
