# Лотерейный анализатор Столото

Версия **40.4.0_15102026**. Загружает архивы тиражей stoloto.ru, проверяет игры на
случайность, честно сравнивает методы прогноза на истории, строит прогноз на следующий
тираж и ведёт журнал: каждый прогноз записывается до тиража и сверяется после него.

> Честная лотерея непредсказуема: если тиражи независимы, ни один метод не угадывает
> больше случайного выбора. Приложение проверяет это на данных, а не обещает выигрыш.
> Итоги проверки на реальных данных — в `docs/AUDIT.md`.

## Установка (Windows)

Подробная инструкция с проверками и решением проблем — [docs/INSTALL.md](docs/INSTALL.md).

Нужны **Git**, **Python 3.10+** (при установке отметьте «Add python.exe to PATH») и
**Node.js 20+** или **Bun**.

1. Скачайте программу:
   `git clone https://github.com/alzhelez/lottery-project.git C:\lottery-project`
2. Запустите **`setup.bat`** (двойным щелчком или из консоли). Он создаст окружение Python
   `.venv` в папке проекта, установит библиотеки Python и зависимости интерфейса. Если Python
   или Node.js не установлены, предложит поставить их через `winget` (после этого запустите
   `setup.bat` ещё раз).
3. Запустите **`start.bat`** и откройте http://localhost:3000. Если тиражей ещё нет, окно
   загрузки откроется само.

4. **Обновление** — `update.bat`: скачивает новую версию с GitHub и обновляет библиотеки;
   данные и настройки не трогает.

5. Чтобы журнал прогнозов пополнялся сам, запустите **`schedule.bat`** — задача в
   Планировщике Windows раз в час загружает тиражи и делает прогнозы по активным играм
   (`schedule.bat 3` — раз в три часа, `unschedule.bat` — отключить).

> `lp.bat`, `start.bat` и `schedule.bat` сами проверяют окружение Python `.venv`: если его нет
> (например, после распаковки обновления) или оно сломано, оно создаётся заново и библиотеки
> доустанавливаются — запускать `setup.bat` повторно не нужно.

### Docker

```bash
docker compose up -d
```

Приложение — http://localhost:3000 (порт открыт только для этого компьютера: в приложении
нет входа по паролю, поэтому из локальной сети оно недоступно; чтобы открыть доступ,
уберите `127.0.0.1:` в `docker-compose.yml`), второй контейнер раз в час выполняет
автозапуск. Данные
хранятся в `./data` рядом с `docker-compose.yml`; при первом запуске туда копируются тиражи
из образа.

## Как пользоваться

1. **Загрузить тиражи** — скачивает архивы всех игр, уже скачанные только докачиваются.
   Затем все игры проверяются на случайность, а прогнозы из журнала сверяются с новыми
   тиражами.
2. **Активные игры** — сколько тиражей, за какой период, номер следующего тиража и вердикт
   проверки. Игры, в которых не было тиражей больше 15 дней, вынесены в список
   **«Устаревшие игры»** (порог — `inactive_days` в `config/games.json`).
3. **Страница игры** — ссылка на игру на stoloto.ru, данные архива и вкладки:
   * **Обзор** — тесты случайности и частоты чисел;
   * **Сравнение методов** — как ~20 методов угадывали на истории (отбор и контроль),
     прогноз лучшего метода и числа, которые чаще всего повторяются в прогнозах;
   * **Режим Бога** — потиражная адаптация моделей с бюджетом времени до 8 часов;
   * **Журнал прогнозов** — прогнозы на будущие тиражи и их сверка с результатом;
   * **Шансы** — точная вероятность каждого исхода билета, ожидаемый выигрыш и возврат
     с рубля; цена билета и типичные выплаты берутся из архива тиражей, свои значения можно
     ввести поверх;
   * **Билеты** — генератор «непопулярных» комбинаций и проверка своей комбинации;
   * кнопка **Экспорт** — всё в Excel или отдельные таблицы в CSV.
4. **Шансы игр** (меню сверху) — сравнение игр по шансу главного приза и возврату.
5. **Автозапуск** на главной — последний цикл и запуск вручную.

### Режим Бога

Пул моделей растёт стадиями (базовые → сетка параметров → бустинг → поиск комбинаций
признаков) до конца бюджета или пока поиск перестаёт находить улучшения — тогда режим
завершается досрочно с пометкой «перебор исчерпан». Состояние сохраняется на диск: если
окно закрыли или время вышло, кнопка **«Продолжить»** (или `lp.bat godmode --game X --resume`)
продолжит с того же места. После загрузки новых тиражей продолжение невозможно — только
новый запуск. Запуск из консоли или Планировщика тоже виден на странице игры.

Сохранение занимает место только пока оно нужно: история угадываний хранится компактно
(байт на тираж вместо четырёх), состояние удаляется, когда перебор исчерпан, когда
загружены новые тиражи (продолжить всё равно нельзя) и если ему больше 14 дней.

### Шансы и билеты — честно

Выбор чисел не меняет вероятность выигрыша. Калькулятор показывает её точно, а по закону
«О лотереях» (ст. 10) призовой фонд — не меньше 50% выручки: в среднем лотерея возвращает
около половины ставок. Генератор «непопулярных» комбинаций не повышает шанс, но в категориях,
где приз делится между победителями, уменьшает ожидаемое число соседей по выигрышу.

**Выплаты из архива.** При загрузке тиражей сохраняются категории выигрышей, число
победителей и суммы (`data/draws/prizes_<игра>.jsonl`). По ним:

* калькулятор шансов подставляет медиану выплат за последние 50 тиражей и цену билета;
* сравнение методов показывает колонку **«в рублях»**: сколько вернул бы каждый метод на
  билет за 1 ₽ против случайного выбора на тех же тиражах (отбор и контроль отдельно);
* журнал показывает **«Выиграно, ₽»** по каждому сверенному прогнозу.

Ответ API Столото о выплатах не документирован, поэтому разбор ищет категории по нескольким
вариантам полей. Если выплаты не появились, выполните `lp.bat diagnose --api` и пришлите
`data\diagnose.txt` и папку `data\api_samples` — разбор подстроится под фактический формат.

**Популярность чисел.** Если в тираже выпали «любимые» числа игроков, победителей больше
обычного. Модель (гребневая регрессия логарифма числа победителей на выпавшие числа,
со скользящей медианой против роста и падения продаж) оценивает популярность каждого числа,
а перестановочный тест проверяет, что связь не случайна. Если она значима, генератор билетов
оставляет только комбинации из 30% наименее популярных; если нет — опирается только на эвристики
(даты, ряды и т. п.). Вердикт показан на вкладках «Сравнение методов» и «Билеты».

Перед прогнозом загрузите свежие тиражи: прогноз, сделанный уже после тиража, журнал
пометит «после тиража» и не засчитает. Для устаревших игр прогнозы в журнал не пишутся.

### Бинго-игры

Русское лото, Жилищная лотерея, Бинго-75 и другие игры с переменным количеством чисел
анализируются по блокам:

* **Невыпавшие числа** — какие числа не выйдут в тираже (для Русского лото и Жилищной
  лотереи API отдаёт именно их);
* **Первые 10 шаров** — если порядок выпадения известен (API отдаёт шары по порядку).

Случайный выбор для сравнения учитывает, что размер множества меняется от тиража к тиражу.

## Командная строка

Из папки проекта:

```bat
lp.bat fetch
lp.bat fetch --game 4x20
lp.bat scan
lp.bat analyze --game 4x20
lp.bat godmode --game 4x20 --budget 60
lp.bat journal
lp.bat auto
lp.bat odds
lp.bat tickets --game 6x45 --count 5
lp.bat export --game 4x20
lp.bat info --game 4x20
lp.bat diagnose
lp.bat telegram setup
```

| Команда | Что делает |
|---------|------------|
| `fetch` | загрузить или обновить тиражи всех игр (`--game` — одной игры) и сверить журнал |
| `scan` | проверить все игры на случайность (пересчитываются только изменившиеся игры, параллельно) |
| `analyze --game X` | сравнение методов и прогноз на следующий тираж (пишется в журнал) |
| `godmode --game X --budget N` | режим Бога, бюджет N минут (1–480) |
| `godmode --game X --budget N --resume` | продолжить режим Бога с сохранённого места |
| `journal` | сверить журнал прогнозов и показать итоги |
| `auto` | цикл автозапуска: загрузка, сверка журнала, анализ активных игр (`--every 1` — повторять каждый час, `--godmode-budget N` — ещё и режим Бога) |
| `odds [--game X]` | шансы и ожидаемый возврат |
| `tickets --game X --count N` | непопулярные комбинации (`--check "1,2,3,4\|5,6,7,8"` — проверить свою) |
| `export --game X [--format csv --what draws]` | экспорт в Excel или CSV |
| `info --game X` | сведения об архиве игры |
| `diagnose [--api]` | проверка формата, полноты данных и выплат по каждой игре, отчёт в `data\diagnose.txt` (`--api` — ещё и сырые ответы API в `data\api_samples.json`) |
| `telegram status \| setup [--chat ID] \| test` | уведомления в Telegram: состояние, настройка id чата, тестовое сообщение |

`lp.bat` — это `.venv\Scripts\python.exe python\lp.py`. В консоли команды пишут понятный
текст, а при запуске из приложения — служебные события.

## Уведомления в Telegram

Итоги сверки прогнозов, автозапуска (с прогнозами на следующие тиражи), режима Бога и
ошибки. Пошагово, с ответами на частые проблемы — [docs/TELEGRAM.md](docs/TELEGRAM.md). Коротко:

1. @BotFather → `/newbot` → токен в `.env`: `TELEGRAM_BOT_TOKEN=...`
2. Открыть своего бота и нажать «Запустить».
3. `lp.bat telegram setup` — сам запишет `TELEGRAM_CHAT_ID`.
4. `lp.bat telegram test`.

## Настройки

Скопируйте `.env.example` в `.env`. Если API Столото отвечает HTTP 401/403, обновите
`STOLOTO_TOKEN` и `STOLOTO_COOKIE` значениями из браузера (инструкция в `.env.example`).
Путь к Python можно задать в `PYTHON_BIN`.

## Тесты

```bat
.venv\Scripts\python -m pytest tests\pytest
npm run build
npx playwright install chromium
npm run test:e2e
```

Сквозные тесты поднимают мок API Столото (`tests/mock_stoloto/server.py`) и работают
с отдельной папкой данных — ваши данные не затрагиваются.

**API-автотесты** на Python, Go и Java — одни и те же 14 сценариев, каждая строка
прокомментирована. Подробности и таблица сценариев — `tests/api/README.md`.

```bat
npm run test:api:env
npm run test:api:py
npm run test:api:go
npm run test:api:java
npm run test:api:env:stop
```

**Allure-отчёт** (Allure 3, Java для него не нужна) собирается из всех результатов, которые
есть в `allure-results/`:

```bat
npm run test:py:allure
npm run test:e2e
npm run allure:report
npm run allure:open
```

**CI** — `.github/workflows/ci.yml`: pytest на Linux (Python 3.10 и 3.13) и Windows,
сквозные тесты, API-автотесты на трёх языках, общий Allure-отчёт как артефакт сборки. Чтобы публиковать отчёт на GitHub
Pages: в настройках репозитория Pages → Source: GitHub Actions и переменная
`ALLURE_PAGES=true` (Settings → Secrets and variables → Actions → Variables).
